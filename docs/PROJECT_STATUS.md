Characters `Trim()` does not remove (zero-width space U+200B, U+FEFF, soft hyphen, …) and inner whitespace are accepted by both sides. With the existing unique `(CompanyId, Email)` index this makes email uniqueness case-insensitive within a company. It **never rewrites, merges or deletes data**: `Up()` first sets `lock_timeout` to 15 s and runs a guard (the same trim list) that aborts the whole transaction with a message (counts only) if any existing email is not normalized or if two users of one company would collide after normalization. `Down()` drops only the constraint. Because migrations run automatically at application start, a violating production row would make the deployment fail to start until the data is fixed — hence the preflight below.

**Tested (VERIFIED 2026-10-14, disposable containers only; 252-test suite all passing):**
